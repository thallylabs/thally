Use `<Note>`, `<Tip>`, `<Info>`, `<Warning>`, `<Check>`, and `<Danger>` to draw attention to content, or make a custom callout. Each type carries one colour; the fill, border, icon and text all derive from it.

</Note>

## With a title and body

Add a title when the callout carries more than a sentence. The title takes the colour; the body stays in ink so paragraphs and links remain readable.

<Note title="Check workspace capacity before you publish">
  Review [managed-site capacity](/guides/deploying) before creating another site. If the workspace is at its active-site limit, an owner can add recurring capacity or delete another Cloud site without deleting that site's GitHub repository or documentation files.
</Note>

<Warning title="Rotating the signing secret invalidates in-flight webhooks">
  Deliveries signed with the previous secret fail verification after rotation. Drain the queue or accept both secrets for the `grace_period` before you rotate.
</Warning>

```mdx
<Warning title="Rotating the signing secret invalidates in-flight webhooks">
  Deliveries signed with the previous secret fail verification after rotation.
</Warning>
```

A callout without a title but with several paragraphs or a list also keeps its body in ink. Only a single sentence takes the colour.

## Custom callouts

The generic `<Callout>` takes any icon and a colour. Fill, border and text derive from the one colour you pass.

<Callout icon="key" color="#C77DFF">
  This is a custom callout
</Callout>

```mdx
<Callout icon="key" color="#C77DFF">
  This is a custom callout
</Callout>
```

Custom callouts get exactly one colour, and no dark variant is generated for it. Pick a colour that stays readable on both page backgrounds (at least 4.5:1 against the light and the dark surface), or pass `colorDark` to use a different colour when the dark theme is active.

```mdx
<Callout icon="key" color="#7B3FB8" colorDark="#C77DFF">
  This callout uses a deeper purple on light and a brighter one on dark
</Callout>
```

Icon names come from the same allowlist as the [Icon component](/components/icons). An unknown name falls back to a neutral help glyph.

Content migrated from other platforms may use the generic form with a `type` instead of a colour. That form is supported as an alias:

```mdx
<Callout type="check">
  This maps to a Check callout.
</Callout>
```

## Props

Every callout accepts arbitrary MDX children including inline code, links, and lists.

| Prop | Applies to | Description |
| --- | --- | --- |
| `title` | All | Optional heading. It takes the callout colour while the body stays in ink. |
| `icon` | All | Replaces the type icon with a named icon from the allowlist. |
| `color` | All | One CSS colour that drives the fill, border, icon and text. |
| `colorDark` | All | Colour used instead of `color` when the dark theme is active. |
| `type` | `<Callout>` | One of `note`, `tip`, `info`, `warning`, `check`, `danger`, plus the aliases `success` and `error`. |
