## Before you begin

You need [Node.js](https://nodejs.org/) 20.9 or later, npm, a terminal, and a
code editor. You do not need an account, API key, or database.

Thally uses a docs-as-code workflow. You write pages as MDX files, organize
them in `docs.json`, preview changes locally, and commit them with the rest of
your project.

## Create your documentation site

Run the non-interactive setup to create a project and install its dependencies:

```bash
npx create-thally-docs my-docs --yes --install
cd my-docs
npm run dev
```

Open the URL printed in your terminal. The server starts at
[http://localhost:3040](http://localhost:3040) and moves to the next available
port when 3040 is already in use.

<Note type="info" title="Want to choose the name, brand, and repository?">
Run `npx create-thally-docs my-docs --install` without `--yes` to use the guided
setup.
</Note>

## Know the three files you will edit

| File | What you control |
| --- | --- |
| `src/content/*.mdx` | Page content and frontmatter |
| `docs.json` | Tabs, sidebar groups, page order, and optional features |
| `src/data/site.ts` | Product name, description, links, and versioned brand defaults |

## Make your first content change

<Steps>

<Step title="Create a page">

Create `src/content/first-page.mdx`:

```mdx
---
title: Your first page
description: A short page created during the Thally quickstart.
---

You created this page with Markdown. Because it is MDX, you can also use
Thally components when you need callouts, steps, cards, tabs, or diagrams.

## What to do next

Replace this example with the first task your users need to complete.
```

</Step>

<Step title="Add the page to your sidebar">

In `docs.json`, add the page ID to the `Start here` group:

```json
{
  "group": "Start here",
  "pages": ["introduction", "quickstart", "first-page"]
}
```

Page IDs match file paths under `src/content/` without the `.mdx` extension.
Save the file and the sidebar updates without restarting the server.

</Step>

<Step title="Open your page">

Select **Your first page** in the sidebar. Confirm that the title, description,
body, and new sidebar entry all appear as expected.

</Step>

<Step title="Validate the project">

In a second terminal, run:

```bash
npx thally check
```

Resolve any errors before you publish. Warnings identify content that may need
attention but do not block a build.

</Step>

</Steps>

## What you accomplished

- Created a complete documentation project without an account or hosted service
- Added a real MDX page and placed it in the sidebar
- Previewed the result locally
- Checked the content and navigation before publishing
